## 1.3 操作机器人的标准顺序（**USB 遥控器 · 正统 RC 通路**）

### 前置：遥控器必须进 USB 摇杆模式

插上 USB 后**在遥控器屏幕上选 `USB Joystick (HID)`**（EdgeTX 会弹
Storage / Serial / Joystick 三选一）。没选的话电脑上什么设备都没有。

验证：

```bash
lsusb | grep 1209        # 必须看到 1209:4f54
ls -l /dev/input/js0     # 必须存在
```

### 驾驶流程

```bash
# ── 终端 1：起仿真（保持无窗口，省 CPU）──
cd "$HOME/PX4-Autopilot" && HEADLESS=1 make px4_sitl gz_airground

# ── 终端 2：遥控器直驱（自动摆臂 52° + 自动切 GROUND_DRIVE）──
cd "/home/yuan/robot air-ground/robot_urdf (4)"
python3 joystick_drive.py --rc --send --servo 1.0
```

然后在 PX4 控制台解锁一次：

```
pxh> commander arm
```

**摇杆映射**（`--rc` 模式 = 正统 RC 通路 `RC_CHANNELS_OVERRIDE`）：

| 摇杆 | 作用 | 通路 |
|---|---|---|
| 右摇杆 上下 | 前进 / 倒车 | CH2 → pitch |
| 右摇杆 左右 | 转向 | CH1 → roll |
| 松手 | 停 | pitch=0, throttle=0 |

`CH3`（油门杆）固定发 1500μs、`CH4` 固定 1500μs。
**左油门杆默认不参与控制** —— 它不自动回中，接了会变成常驻满倒车。
要用它调速就加 `--rc-throttle-axis 2`，但启动前必须把杆推到中位。

### ✅ 可以同时开着 QGC

脚本监听 **14551**，QGC 用 **14550**，两者端口分开、互不干扰：

```bash
# 默认就是 14551，不用额外参数
python3 joystick_drive.py --rc --send --servo 1.0

# 需要换端口
python3 joystick_drive.py --rc --send --local-port 14552
```

> ⚠️ **绝对不要把本地端口设成 14550** —— 那是 QGC 的监听口。
> 两个 UDP socket 抢同一端口时，QGC 收不到遥测，表现为「QGC 与 PX4 失联」。
> PX4 是 UDP 服务器（`mavlink start -x -u 18570`），谁给它发包它就回到谁的源端口，
> 所以脚本换个端口就能和 QGC 共存。

实测：QGC 在线时跑脚本 8 秒 ——
`Connection to ground station lost` 计数**没有增加**，
同时 PX4 日志里 `manual_control_setpoint` 出现 `data_source=1 (SOURCE_RC)`，
四个轴回中时全为 0。

> 换到 14551 后脚本收不到 PX4 的 HEARTBEAT（只能收到姿态/位置等数据流），
> 所以界面上的 `armed=` 会显示 `?`。**这不影响控制** ——
> `RC_CHANNELS_OVERRIDE` 是单向发送的。

### ⚠️ 不要用 QGC 的摇杆

QGC v5.0.8 的摇杆归一化对这台遥控器是坏的，实测三路对照（所有杆在正中）：

| 来源 | roll | **pitch** | yaw | throttle |
|---|---|---|---|---|
| 内核 `js0` | 0 | **0** | 0 | ≈0 |
| SDL2 | −81 | **+272** | −49 | 4818 |
| **QGC 算的** | −0.0015 | **+1.000** ❌ | −0.0015 | 0.009 |
| **PX4 收到** | −0.001 | **−1.000** ❌ | −0.001 | −0.984 |

后果：Position 模式下 `pitch=−1` → 速度目标顶到 `MPC_VEL_MANUAL` = **10 m/s**，
机器人会自己一直往前冲（日志实测 88% 的帧都是 −1）。

已排除：INI 键名、轴编号（SDL 与 `js0` 逐位一致）、`Axis1Min/Max/Trim`
被校准写坏（显式改成 −32767/32767/0 后仍出 1）、`ThrottleMode`、`txmode`、重插设备。
**这是 QGC 的问题，改配置解决不了。** 现在 INI 里已设：

```ini
[Vehicle0]
JoystickEnabled=false
```

### QGC 仍然可以用来做这些（不碰摇杆）

- 看飞行状态、日志、参数
- **Actions 按钮**：摆臂档位、切 GROUND_DRIVE、Arm/Disarm
- **Vehicle Setup → Actuators 滑条**：未解锁时调摆臂角度

⚠️ **千万不要点 QGC 的 Takeoff**。摆臂在 52° 时点它会切进 AUTO_TAKEOFF，
飞控的姿态混控会直接推着轮子跑，看起来像「车自己乱走」。

# 第 2 章 · 环境启停

## 2.1 启动仿真

```bash
cd "$HOME/PX4-Autopilot" && make px4_sitl gz_airground
```

就这一条。**PX4 的 Gazebo 永远是无窗口的 `server-only`** —— 它拼出的命令固定是
`gz sim --verbose=1 -r -s <world>.sdf`，**没有任何开关能让它直接带画面**：

| 你可能会试的 | 实际效果 |
|---|---|
| `HEADLESS=1 make px4_sitl gz_airground` | 和上面**完全一样**。`HEADLESS` 只对 jsbsim / gazebo-classic / jmavsim 有效，**对 gz 无效** |
| `PX4_GZ_HEADLESS=0 make px4_sitl gz_airground` | 同上。这个变量在本版 PX4 代码里**已不存在**（早期文档里写过，已过时） |
| 不加任何变量 | 还是 `gz sim -r -s`，无窗口 |

PX4 实际支持的 `PX4_GZ_*` 变量只有这 7 个，里面没有 GUI 相关项：

```
PX4_GZ_MODEL_NAME  PX4_GZ_MODELS  PX4_GZ_PLATFORM_HEADING_DEG
PX4_GZ_PLATFORM_VEL  PX4_GZ_PLUGINS  PX4_GZ_SERVER_CONFIG  PX4_GZ_WORLDS
```

> **想看画面必须另起一个图形客户端**，见 §3.1。

就绪标志：日志出现

```
INFO  [commander] Ready for takeoff!
pxh>
```

## 2.2 关闭与清理（顺序很重要）

### A. 一键关闭（推荐）

```bash
cd "/home/yuan/robot air-ground/robot_urdf (4)"
./stop_all.sh              # 关 Gazebo + 飞控 + 清锁，并自动确认
./stop_all.sh --gui-only   # 只关 GUI，保留仿真
./stop_all.sh --quiet      # 静默，只输出最终结果
```

它会分 6 步做，并在最后告诉你是否真的清空了。

### B. 手动三步（顺序不能反）

```bash
# ① 杀飞控
pkill -9 -f "build/px4_sitl_default/bin/px4"
# ② 杀 gazebo（server + GUI 一起）
pkill -9 -f "gz sim"
# ③ 等进程真的退出，再删锁
sleep 2
rm -f /tmp/px4_lock-*
# ④ 确认没有幽灵世界话题（否则下次启动会卡住，见 §2.2 G）
gz topic -l | grep "/world/.*/clock"    # 必须无输出
```

> **为什么必须先杀进程后删锁**：
> 删完锁再杀进程，进程退出时还会**再写一次**锁文件；
> 而 `/tmp/px4_lock-0` 残留会让下一次启动直接退出。
>
> 若只杀了 `bin/px4` 而包装进程还在，它们可能把子进程重新拉起来：
> ```bash
> pkill -9 -f "cmake -E env PX4_SIM_MODEL"
> pkill -9 -f "px4_sitl_default/src/modules/simulation/gz"
> ```

### C. 只关 GUI（保留仿真）

```bash
pkill -f "gz sim -g"
```

关窗口或 `Ctrl+C` 效果相同。物理仿真不受影响。

### D. 关完确认

```bash
ps -ef | grep "[g]z sim" | wc -l                    # 必须是 0
ps -ef | grep "[p]x4_sitl_default/bin/px4" | wc -l  # 必须是 0
ls /tmp/px4_lock-* 2>/dev/null                       # 不能有输出
gz topic -l | grep "/world/.*/clock"                 # 不能有输出（幽灵话题）
```

> 最后一条最容易被忘了查，但它会造成「启动卡在 Waiting for Gazebo world」（§2.2 G）。

### E. 关不掉的顽固情况

| 现象 | 原因 | 处理 |
|---|---|---|
| `pkill` 后进程还在 | 卡在 D 状态（不可中断 IO） | 等几秒再试；实在不行重启会话 |
| GUI 关了但 server 还在 | 只杀了 `gz sim -g` | `./stop_all.sh`（不带 `--gui-only`） |
| 新实例起不来，提示锁占用 | 旧实例没退干净 | 先确认 `ps -ef \| grep "[g]z sim"` 为空 |
| **卡在 `Waiting for Gazebo world...`** | **幽灵世界话题（§2.2 G）** | `./stop_all.sh`，再确认 `gz topic -l \| grep /world/` 为空 |
| 彻底清干净 | —— | `pkill -9 -f gz; pkill -9 -f px4; sleep 2; rm -f /tmp/px4_lock-*`<br>⚠️ 会杀掉本机**所有** gz/px4 进程 |

### F. 为什么会有「幽灵进程」

PX4 SITL + Gazebo 是一组多进程（`px4` + `gz sim -s` + `gz sim -g`）。
用终端或工具**后台**启动时，关掉终端并不会杀掉子进程。于是：

- 多个 `gz sim` 同时存活 → 各自注册同名话题（如 `/world/airground/pose/info`）
  → GUI 收到互相矛盾的位姿 → **机器人在多个位置之间疯狂闪烁**
- `/tmp/px4_lock-0` 残留 → 下一次启动直接退出

所以**每次测试结束都要显式关闭**，不能只关终端。

### G. 卡在 `Waiting for Gazebo world...`（幽灵世界话题）

**现象**：启动后日志一直在刷

```
INFO  [init] gazebo already running world: airground
INFO  [init] Waiting for Gazebo world...
INFO  [init] Waiting for Gazebo world...
```

而且**加不加 `HEADLESS=1` 都一样卡**。

**原因**：`px4-rc.gzsim` 是这样判断“要不要自己拉起 server”的：

```sh
# 在 ROMFS/px4fmu_common/init.d-posix/px4-rc.gzsim
# Look for an already running world
gz_world=$( gz topic -l | grep -m 1 -e "^/world/.*/clock" | ... )
if [ -z "${gz_world}" ] && [ -n "${PX4_GZ_WORLD}" ]; then
        # 自己拉起 server
else
        echo "INFO  [init] gazebo already running world: ${gz_world}"
fi
```

关键陷阱：**`gz topic -l` 会把「只有订阅者、没有发布者」的话题也列出来**。
一个残留的 `px4` 进程（它的 `gz_bridge` 订阅了 `/world/airground/clock`）
就能让这个判断误中，于是新 PX4 不再拉起 server，转头去等
`/world/airground/scene/info` 服务 —— 但根本没 server 在提供，于是一直等。

**验证**：

```bash
gz topic -i -t /world/airground/clock
# No publishers on topic [/world/airground/clock]     ← 没有 server
#   Subscribers: tcp://127.0.0.1:xxxxx                ← 但有残留订阅者
```

**处理**：

```bash
cd "/home/yuan/robot air-ground/robot_urdf (4)"
./stop_all.sh                              # 新版本会连带检查幽灵话题
gz topic -l | grep "/world/.*/clock"       # 必须无输出，再做下一步
```

> 只要 `ps` 里已经没有 `gz sim` 和 `px4`，幽灵话题会在几秒内自动消失；
> 如果一直不消失，说明还有进程在订阅（`ps -ef | grep -i gz` 再查一遍）。

## 2.3 检查有没有幽灵实例

```bash

# 话题的发布者数量必须是 1；出现 2 个说明有幽灵 server → 画面会疯狂闪烁

```

## 3.2 相机位姿怎么调

`$WS/gz_gui/airground_gui.config` 第 28 行：

```xml
<camera_pose>-0.45 -0.35 0.28 0 0.46 0.66</camera_pose>
```

六个数字 = `x y z roll pitch yaw`（**米 / 弧度**）：

| 量 | 当前值 | 含义 | 改法 |
|---|---|---|---|
| `x y z` | `-0.45 -0.35 0.28` | 相机在车的左后上方 | 想更近就整体乘 0.7，更远乘 1.5 |
| `roll` | `0` | 绕视线滚转 | 保持 0（地平线水平） |
| `pitch` | `0.46` | 俯仰 26°，正 = 低头 | `arctan(z / 水平距离)` = `arctan(0.28/0.57)` |
| `yaw` | `0.66` | 水平朝向 38° | `atan2(|y|, |x|)` = `atan2(0.35, 0.45)` |

# 第 4 章 · PX4 控制台（pxh）

仿真启动后，终端会停在 `pxh>`，命令直接敲。

## 4.1 地面驱动模块

```
ground_drive status          # 全量状态：注册、门控、摇杆、calib 参数、ctrl
ground_drive start           # 手工启动模块（airframe 里已有，一般不用）
```

`status` 里最该看的三行：

```
mode active     : yes                    ← 是否已在地面模式
sticks raw      : thr=+0.00 pitch=+0.00 roll=+1.00 yaw=+0.00 valid=yes
calib           : v_max=1.20 m/s  yaw_gain=1.50 rad/s  turn_slow=1.00
ctrl[a,b]       : -0.0825 / +0.0825      ← 满舵纯搓转的正确值
```

## 4.2 模式与解锁

```
commander mode ext1          # 切到 GROUND_DRIVE（外部模式 1）
commander mode posctl        # 切回 Position
commander arm                # 解锁
commander disarm             # 上锁（正常路径）
commander disarm -f          # 强制上锁
```

`commander mode` 支持的全部模式（源码 `Commander.cpp:3249`）：

```
manual | acro | offboard | stabilized | altctl | posctl | altitude_cruise
position:slow | auto:mission | auto:loiter | auto:course | auto:rtl
auto:takeoff | auto:land | auto:precland | ext1
```

> ⚠️ `auto:takeoff` 就是 QGC 上那个 **Takeoff 按钮**。摆臂在 52° 时切它会
> 让飞控的姿态混控直接推着轮子跑，看起来像「车自己乱走」。

## 4.3 参数

```
param show GD_*              # 看所有地面驱动参数
param show GD_TURN_SLOW
param set GD_TURN_SLOW 1.0
param save                   # ⚠️ 会写进 parameters.bson，下次启动会覆盖默认值
```

`param show GD_*` 的真实输出（应正好 9 行）：

```
x     GD_ARM_MIN_DEG  : 48.0000
x     GD_GEAR_RATIO   : 64.0000
x     GD_MAX_OMEGA    : 2400.0000
x     GD_MAX_SPEED    : 1.2000
x     GD_SERVO_RATE   : 40.0000
x     GD_TURN_SLOW    : 1.0000
x     GD_WHEEL_R      : 0.0400
x     GD_WHEEL_TRACK  : 0.1650
x     GD_YAW_GAIN     : 1.5000
```

开头的符号：`x` = 已使用，`+` = 已保存到 bson，`*` = 未保存，`l` = 已锁定。
出现多一行或少一行都说明参数表被改动过。

> **坑**：`param set` 后 PX4 会异步把参数存进
> `build/px4_sitl_default/rootfs/parameters.bson`。

## 5.2 verify.py 子命令

### 试验摆臂工作角（重要：必须先改阈值）

`armangle` 会在指令层面把摆臂摆到不同角度。但**低于 48° 时 mux 不会驱动轮子**
（`<arm_threshold_deg>`）**、门控也会拒绝**（`GD_ARM_MIN_DEG`），
所以先把两处都降到测试下限以下：

```bash
# ① mux 侧（改一次，实验完记得恢复）
sed -i 's|<arm_threshold_deg>48</arm_threshold_deg>|<arm_threshold_deg>30</arm_threshold_deg>|' \
    "px4_changes/gz/airground/model.sdf"
cp px4_changes/gz/airground/model.sdf \
   "$HOME/PX4-Autopilot/Tools/simulation/gz/models/airground/model.sdf"

# ② 重启仿真后跑（脚本会自动把 GD_ARM_MIN_DEG 设到 下限-5）
./run_regression.sh "armangle --degs 52,45,38,35,34"
```

> 实测结论（详见方案文档 §14.4.2）：
> **34~36° 是 100 % 区间，37° 开始下降，30° 以下轮子悬空。**
> 且直线速度完全不变（0.600 / 1.200 m/s 与 52° 逐位一致）。

## 5.3 判据速查

| 子命令 | 通过标准 |
|---|---|
| `smoke` | 见 §1.1 的预期输出 |
| `repeat` | `|Δψ|` 中位数大且**最小值也大**才算可靠；`最小≈0 且最大>40` = 双稳态（物理限制，见文档 §14.2） |
| `armangle` | 成功率 100 % 且位移中位 > 10 mm（位移≈0 说明轮子悬空）；参考：52°→17 %、38°→50 %、**35°→100 %**、30°→悬空 |
| `steer` S1 | `+roll` 应产生 `Δyaw<0`（右转）；两段严格反号 |
| `steer` S3 | 横向漂移 < 3% 行程，`|Δyaw| < 2°` |
| `steer` S4 | 速度误差 < 10%（标称 1.2 m/s） |
| `reversible` | `cos(θ) ≈ -1.00`（前进/倒车方向相反）；静止段位移 < 0.05 m |

## 7.3 常见字段陷阱

| 陷阱 | 说明 |
|---|---|
| 时间戳回绕 | `d['timestamp'].astype(np.int64) - int(t0)`，不要用 uint64 直接减 |
| `actuator_outputs` 是多实例 | `id=0` = 电机（0~1000，500 中位），`id=1` = 舵机 |
| 摆臂角度 | 没有 `actuator_servos` 话题；从 `actuator_outputs` id=1 的 `output[0]` 反算（`输出/1000 × 52°`） |

# 第 9 章 · QGC 操作

## 9.1 摇杆映射（**最容易踩的坑**）

| 摇杆 | 轴 | 效果 |
|---|---|---|
| 左摇杆 上下 | `throttle` | 前进 / 后退 ✅ |
| 左摇杆 左右 | `yaw` | **完全无效** ❌（代码只读 `roll`） |
| 右摇杆 上下 | `pitch` | 前进 / 后退 ✅ |
| 右摇杆 左右 | `roll` | **转向**（唯一有效的转向轴）✅ |

> 前后两个轴是**饱和求和**的（同向叠加、反向抵消），
> 所以推哪根都行，同时推会叠加到满量程。

## 9.2 Actions 面板

部署 `qgc_actions/AirArmActions.json` 后，QGC 的 Actions 里会出现 **14 个按钮**：

| 序号 | 按钮 | 对应命令 |
|---|---|---|
| 1 | `▲ Arm（解锁）` | `400` p1=1.0 |
| 2 | `▼ Disarm（上锁）` | `400` p1=0.0 |
| 3 | `▶ 进入地面模式` | `176` p1=1 p2=4 p3=11 |
| 4 | `■ 回到 Position 模式` | `176` p1=1 p2=3 p3=0 |
| 5~14 | `摆臂 0° / 6.5° / … / 45.5° / **48°** / 52°` | `187` p1 = `角度/26 − 1` |

摆臂各档与 `param1` 的对应：

| 角度 | 0° | 6.5° | 13° | 19.5° | 26° | 32.5° | 39° | 45.5° | **48°** | 52° |
|---|---|---|---|---|---|---|---|---|---|---|
| `param1` | −1.0 | −0.75 | −0.5 | −0.25 | 0 | 0.25 | 0.5 | 0.75 | **0.85** | 1.0 |

> **关于 48° 这一档**：`GD_ARM_MIN_DEG` 和 mux 的 `<arm_threshold_deg>` 都是 48，
> 所以 48° 是**能驱动轮子的最低角**。这里 `param1` 取 **0.85** 而非精确的 `48/26−1 = 0.8462`，
> 是为了让实际角度落在 **48.1°**、比门限高 0.1°，**避开浮点/取整边界**
> （若机器人恰好停在 47.99°，mux 会判 `groundMode = false`，轮子完全不转）。

## 9.3 顺序

```
摆臂 52° → 进地面模式 → Arm → 行驶
```

⚠️ **永远不要在这种状态下点 Takeoff**。

# 第 11 章 · 故障速查表

| 症状 | 最可能的原因 | 先查什么 |
|---|---|---|
| 进了地面模式但车不动 | 摆臂不是 52° / mux 阈值不一致 | `ground_drive status` 看 `servo cmd` 与 `est angle`；`gz topic -e -t /world/airground/joint_state` 看 `servo_0` 真实角度 |
| 电机全是 `[500,500,500,500]` | 被 `COM_DISARM_LAND` 自动上锁了 | 启动日志里搜 `Disarmed by landing` |
| 摇杆推了没反应 | 摸的是左摇杆左右（`yaw`，死轴） | `ground_drive status` 的 `sticks raw` 行 |
| 车自己乱走 / 压不住 | 摆臂在 52° 但飞控在飞控模式（误点 Takeoff） | `ground_drive status` 看 `mode active`；日志搜「摆臂在轮位但飞控在驾驶」 |
| 未解锁就满速倒车 | `SIM_GZ_EC_DIS*` 不是 500 | `param show SIM_GZ_EC_DIS1` |
| 转向时好时坏 | W/L 偏低的静摩擦锁死（**物理限制**） | 文档 §14.2；先用 `verify.py armangle --degs 52,45,38,35,34` 试 |
| 摆臂低于 48° 时轮子不转 | mux 的 `<arm_threshold_deg>` 与 `GD_ARM_MIN_DEG` 没过 | 两处都改到低于目标角（§5.2） |
| 低摆臂角时车完全不动 | 轮子离地了（30° 以下） | 看 `armangle` 输出里的「位移中位」，≈0 就是悬空 |
| 日志里 `landed` 恒为 false | `vehicle_thrust_setpoint` 没人发 | 确认 `_sp_confirmed` 为 true，模块在跑 |
| 编译报 `Parameter Name XXX is too long` | PX4 参数名上限 **16 字符** | 改名 |
| 改了 module.yaml 默认值没效果 | `parameters.bson` 里有旧值 | 写进 airframe，或删 bson |
| 启动即退出 | `/tmp/px4_lock-*` 残留 | `rm -f /tmp/px4_lock-*` |
| 画面疯狂闪烁 | 多个 `gz sim` 实例 | `pkill -9 -f "gz sim"` |
